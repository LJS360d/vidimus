# r12s: responsiveness

`r12s` (responsiveness, like a11y for accessibility) loads every page at several narrow viewport widths and measures the rendered layout. It finds the problems that only show on a phone: a table or code block that makes the whole page scroll sideways, links too small or too close together to tap, text too small to read, and a viewport meta tag that is missing or stops users from zooming.

## Needs

```sh
npm i -D puppeteer
```

The audit loads pages over HTTP (`requires: 'server'`): vidimus serves the build locally, or uses `--origin`.

## Run it

```sh
npx vidimus r12s
```

It is part of the default set.

## What it checks

Every built page that is not excluded is loaded at every width in `r12s.viewports`, in every locale: translated text is often longer and breaks layouts that fit in the default language. The viewport is 800px tall, and widths below 768px are emulated as a mobile device with touch. After the `load` event vidimus waits for web fonts, then measures. If the page navigates away while being measured (a meta refresh or script redirect), it waits for the new page and measures that instead, once. With `r12s.sample`, pages whose URL path matches a pattern are reduced to the first matching page per pattern; pages that match no pattern are all loaded.

### overflow

The page scrolls sideways: the document is more than 1px wider than the viewport. The finding lists up to five of the innermost elements that stick out past the end edge (the right edge, or the left one on a right-to-left page), with their width and right edge in px, so you see the element causing it rather than every ancestor. Elements inside a box that scrolls or clips them, such as code in a `<pre>` with `overflow-x: auto`, are not listed: they do not make the page scroll. Content that needs a two-dimensional layout is exempt under WCAG 1.4.10, so tables, images, SVG and canvas (and anything inside them) are not listed either. Embeds (`<iframe>`, `<video>`, `<embed>`, `<object>`) are still listed, because their size can be set with CSS.

An `<iframe>`, `<video>`, `<embed>` or `<object>` with fixed `width`/`height` attributes (YouTube's default `width="560"`) is the usual cause on phones; when one is listed, the fix suggests sizing it with CSS instead:

```css
iframe { width: 100%; height: auto; aspect-ratio: 16 / 9; }
```

### target-size

A link (`a[href]`), `button`, `input`, `select`, `textarea` or `[role="button"]` smaller than `r12s.minTarget` in either dimension, for which a circle of diameter `minTarget` centred on its box overlaps another target: the circle must not intersect another target's box, and for an undersized neighbour, not its circle either. This is the spacing exception of WCAG 2.2 success criterion 2.5.8 (Target Size, Minimum). Elements that are not rendered (`display: none` on themselves or an ancestor), have no size, or are hidden by `visibility: hidden` or `opacity: 0` on themselves or an ancestor are not counted. Inline links inside a sentence (an `inline` element whose parent also holds text) are exempt, as in WCAG 2.5.8.

### font-size

An element that directly contains text (its first child is a non-blank text node) with a computed `font-size` below `r12s.minFont`. SVG content and elements that are not rendered or are hidden, as above, are skipped. Screen-reader-only elements are skipped too: an element, or an ancestor, with `clip: rect(0 0 0 0)` (or `rect(1px, 1px, 1px, 1px)` when `position` is `absolute` or `fixed`), or with `clip-path: inset(50%)` or `inset(100%)`.

### viewport

- No `<meta name="viewport">` at all: the page renders at desktop width on phones.
- A viewport meta that disables pinch zoom: `user-scalable=no`, or a `maximum-scale` below 2, which stops text reaching the 200% zoom of WCAG 1.4.4 (Resize Text).

### Grouping

Findings are grouped by rule, measurement and element, and list every width and page where the same defect occurs. A defect in a shared component shows once, with `@320/375px` for the widths and `on:` for the pages. Overflow is usually reported once per width, since its measurement includes the viewport width.

A page that fails to load within `r12s.timeout` becomes a `failed to load /path/` finding, with the widths and the browser error as details; the other pages are still checked.

## Options

| Key | Default | Description |
| --- | --- | --- |
| `r12s.viewports` | `[320, 375, 768]` | widths in px; each page is loaded at every one |
| `r12s.minTarget` | `24` | minimum tap target size and spacing circle diameter in px |
| `r12s.minFont` | `12` | minimum font size in px |
| `r12s.timeout` | `60000` | ms to wait for a page's `load` event |
| `r12s.concurrency` | half the cores (2 to 8) | browser tabs used at the same time |
| `r12s.exclude` | `[]` | URL path patterns to skip, e.g. `^/print/` |
| `r12s.sample` | `[]` | URL path patterns: load one page per matching template |

## Config example

```ts
import { defineConfig } from 'vidimus';

export default defineConfig({
  r12s: {
    viewports: [320, 390, 820],
    minTarget: 44,
    exclude: ['^/slides/'],
  },
});
```

`minTarget: 44` matches the stricter WCAG 2.5.5 (Target Size, Enhanced) criterion.

## Common fixes

Let wide content scroll inside its own box instead of the page:

```html
<style>
  pre, table { display: block; max-width: 100%; overflow-x: auto; }
  img, video, iframe { max-width: 100%; height: auto; }
  a, code { overflow-wrap: anywhere; }
</style>
```

Give icon links a tappable area without changing the icon size:

```html
<style>
  .social a { display: inline-grid; place-items: center; min-width: 24px; min-height: 24px; }
</style>
```

Use a viewport meta that allows zoom:

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

## Tips

- Inline links inside a paragraph are measured too. If they sit on adjacent lines with a small `line-height`, raise the line height.
- Each defect is keyed on the element description, so the same problem on elements with different text (each post's byline) produces one finding per text. A top-level `ignore` rule matches the message, not the element, so `{ audit: 'r12s', message: '^font-size', where: '^/archive/' }` silences small text on a section rather than one element.

## Standards

### WCAG 2.2

[WCAG 2.2](https://www.w3.org/TR/WCAG22/)

- 1.4.10 Reflow: sideways overflow caused only by a table, img, picture, svg or canvas (or anything inside one) is not reported.
- 1.4.10 Reflow: an overflowing element that is not perceivable (not rendered, `visibility: hidden`, `opacity: 0`, or screen-reader-only) is never named as the cause.
- 1.4.4 Resize Text: a viewport meta with `user-scalable=no` or `user-scalable=0` is reported.
- 1.4.4 Resize Text: a viewport meta whose `maximum-scale` is below 2 is reported.
- 2.5.8 Target Size (Minimum), spacing exception: an undersized target is reported when its `minTarget` circle intersects another target's box, or that neighbour's circle when the neighbour is undersized too. Sizes are compared unrounded, so a 23.6px target is undersized; only browser layout rounding (1/64px) is tolerated.
- 2.5.8 Target Size (Minimum), inline exception: an inline element whose parent also holds text is not measured as a target.

### CSS Device Adaptation

[CSS Device Adaptation](https://drafts.csswg.org/css-device-adapt/)

- Meta viewport: `user-scalable` and `maximum-scale` are read from the first `meta[name="viewport"]`; the spec defines `maximum-scale` as a `@viewport` descriptor.
- Meta viewport: a page with no viewport meta is reported (vidimus check, no clause).

### Not checked

- 1.4.4 Resize Text at 200% zoom and 1.4.12 Text Spacing: pages are never re-rendered zoomed or with spacing changed; only the viewport meta is read.
- 1.3.4 Orientation: the height is fixed at 800px, so landscape layouts are not measured.
- 2.5.5 Target Size (Enhanced, AAA): no separate check; `minTarget` sets the size that 2.5.8 uses.
- 2.5.8 equivalent and essential exceptions: not modelled, only the inline exception is.
- Targets: `label`, `[tabindex]` widgets and `summary` are not counted as targets.
- Viewport meta: only the first `meta[name="viewport"]` is read, and its `width` and `initial-scale` values are not validated.
- Minimum font size: no WCAG success criterion sets one; `minFont` is a vidimus threshold.
